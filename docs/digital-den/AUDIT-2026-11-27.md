# Digital Den repair audit — 27 November 2026

Scope: GitHub issues **#2–#57**, Arete and Homie. This report separates deployed
repairs, bounded observations and acceptance that still needs longer evidence.
It does not turn a service restart into a graphics fix or a short sample into a
24-hour leak test.

## Measured causes, not dashboard guesses

### Idle work and retained resources

- A parked remote cursor left bar hover state active. That kept ambient motion
  running on the wrong host. `ShellState.qml` now qualifies per-bar hover by the
  cursor broker's atomic ownership record. Overlapping bars and ownership changes
  were exercised in a native QML regression.
- Wallpaper images decoded at full source resolution before their view had
  geometry. Guarding the actual image request reduced a fresh native 7680×4320
  fixture's peak RSS from **177.64 MiB to 53.15 MiB**. This is a specific image
  allocation result, not a percentage reduction for the whole desktop.
- Video engines accumulated for previously visited outputs. `YouTubeDesk.qml`,
  `MpvEngine.qml` and `MusicVideoSurface.qml` now release inactive engines and
  unregister the exact destroyed owner. Native decoded-video handoff preserved
  position, pause and volume across every connected output on both hosts.
- Homie's transparent huge pages inflated sparse cursor allocations. With the
  same isolated native workload and approximately 3.118 MB live allocator
  allocations, default Homie PSS was **68,597 KiB**, versus **32,716 KiB** with
  process-only THP disabled. No machine-wide THP, swap or compute policy changed.
  `pc/den/den-cursor.service` owns that narrow policy.

A completed 61-sample, ten-minute observation before the final matched runtime
adoption measured the following. CPU is percent of **one CPU core**, not percent
of the whole machine. Displays, hardware and application activity differ.

| Host | Main shell mean CPU | Main PSS first → last | Compositor mean CPU | Cursor mean CPU |
|---|---:|---:|---:|---:|
| Arete | 0.46% | 526.77 → 526.15 MiB | 3.58% | 0.97% |
| Homie | 0.29% | 628.40 → 645.05 MiB | 0.22% | 0.02% |

Every monitored PID survived that observation. It is not the final post-change
24-hour acceptance, and the Homie increase alone is not proof of a leak.

### Graphics root cause and repair — #3

The production core's null `dri2_query_image` argument was reproduced in a
disposable native EGL program and an actual resizable Quickshell layer surface.
Mesa's `get_back_bo` reserved a back buffer, failed to allocate its image, then
left the reservation non-null. A subsequent render trusted that invalid buffer.
The inspected production display/render file descriptors belonged to the same
GPU; a decoder-specific, cross-GPU or stale-NVIDIA explanation was not established.
Allocation failure does not by itself prove system RAM exhaustion.

This defect was already fixed upstream by
[Mesa MR !44569](https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/44569),
commit `3d2a7e8ad2e09bb5b9b532121bc45230a55221b2`. The backport clears the failed
reservation on all five allocation-error exits and preserves `EGL_BAD_ALLOC`.
The 26.2.8 maintenance source contains it; the inspected 26.3.1 candidate does
not. Release numbers or a process remaining alive were not treated as proof.

A second defect became observable after repairing Mesa: Qt requested a Wayland
frame callback before the failed swap. No surface commit occurred, so that
callback never arrived and Qt indefinitely withheld subsequent updates. The
downstream Qt 6.12 correction cancels the uncommitted callback through Qt's
existing locked teardown and queued GUI-thread delivery. It adds no class data
members, preserves the EGL warning, and does not recreate or hide the window.
This Qt correction is local; no upstream Qt fix is claimed.

| Native controlled case | Process | Compositor pixels after the fault clears |
|---|---|---|
| Installed system Mesa/Qt | SIGSEGV at the production EGL chain | No recovery |
| Mesa rollback alone | Survives | Frozen despite a live QML timer |
| Mesa rollback + Qt failed-commit recovery | Survives | Drawing resumes automatically |

The permanent regressions detect all three original failures on Arete's system
libraries; the repaired set passes all three. Homie passes both native widget
tests. Its proprietary GPU does not expose a Mesa DRI screen, so the
allocator-internals case is explicitly skipped there, not reported as passing.
Vendor-independent swap-failure tests exercise both actual desktops under both
`basic` and `threaded` render loops. Sustained 1.2-second failures preserve error
reporting and recover visible frames without a workspace switch or another resize.

`scripts/build-mesa-wayland-backport.py` builds only EGL and its utilities from
pinned 26.2.4 source. It links the **installed** Gallium and GBM, preserves EGL
exports, rejects unresolved dependencies/RPATH, and fingerprints its actual
system inputs. It does not compile or install another GPU driver.
The paired Qt builder preserves the installed client/plugin exports and licenses.
Both retain prior private prefixes; neither replaces distro libraries.

Both production main shells adopted the pair at 23:11 Asia/Dhaka. Their actual
process mappings show the repaired EGL, Qt client and Qt EGL plugin. Native video
handoffs work across Arete's three outputs and Homie's two outputs with normal
GPU texture conversion; the speculative decoder-conversion workaround was removed.
Input, cursor and clipboard service PIDs/restart counts did not change.

The `basic` loop remains a scoped performance choice, not the crash fix.
Earlier controlled lifecycle measurements explain that choice:

| Host / loop | Completed surface lifecycles | Elapsed seconds | CPU seconds |
|---|---:|---:|---:|
| Arete / threaded | 750 | 30.84 | 9.34 |
| Arete / basic | 750 | 25.21 | 5.45 |
| Homie / basic | 500 | 25.18 | 3.75 |
| Homie / threaded | 200 before the bound | More than 45 | Unknown |

The bounded Homie run was not classified as a deadlock. `QSG_RENDER_LOOP`
remains overridable. See [Qt's render-loop documentation](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html).

Final-process 24-hour measurements are running independently on both hosts.
**#2, #3 and #6 remain open** until their extended-observation criteria are met;
the functional root-cause proof is not a substitute for those measurements.

## Lifecycle and UI ownership — #4, #10, #11, #14, #21, #22, #24, #31, #34

Owned workspace, phone and radio watchers bind to their parent lifetime. A dead
observer marks data stale and restarts through a bounded path. Killing the actual
workspace/radio child on each host produced stale → recovered state without
restarting the main shell. Workspace scanning is event-driven with a reconciliation
fallback: two scans were observed over 35 idle seconds, not one every three seconds.

The monitor has one 1 Hz stream only while its view is active, separate expensive
inventory, a locked atomic cache and unique temporary files. Closing the panel
stops the producer. The service launcher has a finite compositor preflight, so
`active` cannot mean an indefinite startup wait. PC wallpaper selection resolves
connected outputs rather than inventing an eDP-1 file; native URLs were checked
against existing files on both hosts.

Notification expiry/hover/resume and persistent critical cards were exercised
against the actual native component. Pausing an already stopped animation is no
longer requested.

A real focus defect was reproduced: changing the global clipboard dropdown
focused search fields in hidden cached windows. Clipboard focus now belongs to
its visible, enabled, active window; Wi-Fi passphrase requests and comic focus
use the same native-window boundary. Each popup has its own `FocusScope`.
`sensei` IPC `popup-OUTPUT focusState` returns only focus/visibility flags, never
field text or passwords. A native component regression fails before the fix and
passes afterward; live output-addressed popup cycles also verify exclusive search
ownership and closed-window release.

The remaining **#11** warnings had a separate Qt caller defect:
`QWaylandInputContext::setFocusObject` tried to disable the new window's surface,
including when no previous surface had been enabled. The reviewed upstream
[QTBUG-141475 correction](https://github.com/qt/qtbase/commit/0d4f9625f6873c82ff463ae77a97b6ec9f81ab4a)
disables only its actual `mCurrentWindow`. The warning guard itself is unchanged;
IME protocols and logging categories remain enabled.

On **each host**, ten real Wayland text/non-text focus transitions reproduced
20 warnings with system Qt and zero with the backport. The candidate preserved
every installed exported ABI symbol. After scoped adoption, nine production
popup cycles across Arete's three outputs and six across Homie's two outputs
completed with exclusive search focus and **zero** disable warnings.
Input-sharing and cursor service PIDs/restart counters did not change.

`scripts/build-qt-wayland-backport.sh` rebuilds only the Wayland client and its
EGL integration plugin from pinned Qt 6.12.0 source; it does not install system
Qt or another graphics stack. The supervisor selects them only while the
system inputs and candidates retain their recorded checksums. Private Mesa
selection also requires Qt's matching failed-commit recovery.
Explicit alternative runtimes and crash fallback do not inherit these overrides.
The builder retains its previous prefix, rejects missing ABI exports/runtime
search paths, includes licenses, and bounds compilation to two low-priority jobs.
Its stable CMake module path works from both repository and deployed invocations.
After an input-library update, stale prefixes are ignored: check upstream before
building another backport. A QML reload does not reload already mapped libraries;
adoption requires a new **main-shell** process, not an input/compositor restart.

Regression suites: `test_desktop_audit.py`, `test_workspace_event_recovery.py`,
`test_den_session_ready.py`, `test_media_engine_lifetime.py`,
`test_notification_lifetime.py`, `test_popup_focus.py`, `test_bar_hover_native.py`.
Native tests require an explicitly selected `SENSEI_QS_BINARY`.

## Connections and media — #7, #8, #12, #41, #42, #43

The actual Den flapping had two causes: the receiver's firewall peer set retained
an old DHCP address, and reverse status recursively requested another cross-host
status. The forced command now exposes a bounded authenticated ping. The root
peer reconciler resolves the configured `.local` name, verifies its pinned SSH
identity and updates only the named firewall peer set. Both directions were
exercised with fresh authenticated handshakes. Do not add static-IP workarounds
or automatically trust a changed host key.

The ordinary SSH client now selects those same pinned profiles for `homie.local`
and `arete.local`, not just their internal aliases. Fresh non-multiplexed
`ssh homie.local hostname` and reverse `ssh arete.local den-control ping` both
succeed. The reverse key remains restricted Den control, not a general shell.
No IP address, host key, credential or authorization scope was changed.

Mode changes release input before persisting AWAY. Peer errors are visible and
same-mode retries reconcile acknowledgements. Wi-Fi hidden joins use the existing
serialized operation queue rather than bypassing it.

Spotify has bounded service restart backoff and one playback owner. A transient
queue fetch failure preserves the cached queue/checkpoint and returns a stale
warning instead of blanking the UI. Controlled HTTP-503/recovery tests cover the
failure path; native status and restart counters were checked on both hosts.
No claim is made that Spotify's provider cannot fail or throttle.

Actual isolated Syncthing instances on both hosts converged file checksums after
an unavailable relay-discovery endpoint and peer stop/restart. Production local
TLS connections and relay DNS resolution were also checked. Discovery failure is
not automatically a failed local synchronization.

For **#12**, the warnings originate in KDE Connect, not Quickshell. Inspected
Avahi records resolved; timeout identifiers belonged to other advertisers, not
the two desktop identities. The sampled count fell from the issue's 594/24 h to
62/24 h, with zero in the final one-hour sample; different observation dates are
not a controlled performance comparison or a promise of zero future timeouts.

The previously unavailable paired phone became reachable. Its trusted D-Bus
identity, reachability and actual battery data were verified without sending
notifications, changing pairings or granting input access. `sensei-status discovery`
now reports usable paired links separately from resolver warnings, sleeping peers,
no configured pairing and incomplete queries. It omits names, device IDs, addresses
and verification keys. Native queries took 0.065 s on Arete and 0.097 s on Homie;
there is no new background poll. The existing CLI deliberately waits two seconds
for discovery, so this snapshot queries the daemon directly instead.
Pairings, identities, IPv6 and multicast policy were preserved.

Tests: `test_den_peer_firewall.py`, `test_den_control.py`,
`test_desktop_job_safety.py`, `test_spotify_headless.py`.

## Rebuild scoped graphics candidates

These builders require the installed Qt 6.12.0 development files, Mesa 26.2.4,
Wayland/GLVND/DRM/X11 development files, a C/C++ compiler, CMake, Ninja,
pkg-config, Meson and Python Mako. They verify the actual inputs rather than
assuming another host's binaries are ABI-compatible.

```sh
python3 scripts/build-mesa-wayland-backport.py
bash scripts/build-qt-wayland-backport.sh
```

Builds prepare private candidates; do not reload every desktop or restart input
sharing to adopt them. A newly started main shell checks the fingerprints.
Preserve the previous prefixes for rollback, and prefer a verified fixed distro
release once available rather than carrying an unnecessary backport forever.

## Clean-runner dependencies

Portable CI installs its real native test tools explicitly: a C compiler,
pkg-config, JSON-C/OpenSSL development files, Restic, librsvg's converter and
FFmpeg. The Python requirements include the exercised NumPy version.
The first public run exposed these missing dependencies even though the same
tests passed on the provisioned workstations. The fix is dependency declaration,
not skipping numerical execution, restore verification or actual asset rendering.
Live compositor/input tests remain separately opt-in; a hosted runner is not
evidence about the physical Den's displays or pointer.
