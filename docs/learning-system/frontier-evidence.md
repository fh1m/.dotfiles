# Learning-engine M1: concept investigation

This is the first reviewable slice of the approved first-principles evolution,
on top of the independently deployed `433d2d1` application. It does not close the
original V1 release or claim that the later learning-engine milestones are done.

## Implemented behavior

Concepts, questions and capabilities open a dedicated investigation page in Learn.
The motivating question, bounded knowledge frontier and reconstruction have their
own regions. Wide windows show question and reasoning together; at 200% scale the
learner switches between them without discarding either. Source notes are expandable,
not a permanent competing inspector. Zed typography, warm system surfaces and the
existing pink identity are retained; the page adds no enclosing border grid.

The learner can start an unaided reconstruction, record its actual result, define
an ability and deliberately judge evidence against a criterion and scope. Confidence,
assistance and evidence kind remain separate. A partial attempt does not award an
ability. Simulation, unit tests, sensor measurements and in-water tests have distinct
evidence labels. These are learner judgments, not independently observed certification.

The read projection reduces complete capability histories before paging criteria.
Older decisions remain reachable. Concurrent decisions remain a visible conflict
until a new decision explicitly names all current heads. Later recorded reference
exposure prevents an old attempt from supporting an unaided claim. Retention requires
an unwithdrawn scoped ability, a learner-chosen interval and a later performed,
successful assessment; a scheduled reminder is insufficient.

Existing concept/question/capability/activity/relationship records remain authoritative.
Optional activity fields are additive within schema 2. No vault migration, graph
database, competence percentage or generated learning results are introduced.
Investigation depth uses existing disposition events. Navigation is machine-local,
bounded and versioned; history entries retain exact vault and record identities,
surface and scroll anchors. Drafts stay in the existing protected draft store.

## Native evidence

`scripts/check-noesis-frontier.py` installs into a disposable HOME, runs the actual
Quickshell application and delivers native Qt keyboard and pointer input. It checks
working-page entry, notes, protected reconstruction, Hide stopping worker/watch,
Close/restart/back recovery, 200% reflow, partial result, explicit rejected claim,
native concept creation and two authorized fixture owners sharing a record UUID.
The last check returns to the correct owner rather than merging their context.

The fixture's agent-authored minimal convolution implementation is committed in a
disposable Git repository and executed against NumPy for two kernels. Its actual
JSON output, checksum and commit are linked as artifacts. This verifies the code;
it does not demonstrate the owner's understanding or detector performance. Synthetic
learner states in screenshots are explicitly fixture data.

[Before/after gallery](ui-gallery.md#concept-investigation-and-knowledge-frontier)
and [captured conditions](assets/frontier/after.json) retain the native window renders.
The fixture adds an equivalent Item viewport around existing application content so
native popup overlays are included in capture. Images are not composed mockups or
captures of personal vaults. Main-display DPR is 2; application text scale is recorded
separately. A 184-frame instrumented sample measured p95 17.158 ms. This is frame
interval, not physical input latency or sustained human-use acceptance.

The synthetic 10,000-record benchmark measured rebuild 3.554 s, query p95 29.641 ms,
Today 23.201 ms and capture 106.389 ms. All 124 core and 16 compatibility tests pass.
Existing shutdown checks passed all ten debounce, pending mutation/import, failed-save,
uncertain-receipt and forced-exit scenarios. Scoped installer checks passed two installs,
rollback and protection of later edits/unrelated files. Tests do not establish educational
effectiveness.

## Owner feedback and response

The owner reported that starting reconstruction, finding missing mechanisms and
judging evidence were all unclear. The page now states the sequence directly, uses
‘Try explaining without notes’, ‘Questions still open’ and ‘Assess what this attempt
demonstrates’, and explains when assessment becomes available. A saved result is
required before that action is enabled. Study-depth settings are collapsed by default.
Native interaction checks passed after this change; the owner has not yet confirmed
that it resolves the usability problem in actual learning.

## Release boundary and remaining work

M1 provides the concept/reconstruction/claim software slice. The owner's 20–30-minute
trial and an actual delayed retention demonstration remain required. Foreign evidence
can be attached, but foreign unaided assessments are conservatively not certified by
this projection. Retention is validated by the backend but its native guided form is
deferred to M2. Frontier relationships here are bounded local neighbors; the existing
owner-aware connections remain available, and a dedicated cross-vault frontier picker
belongs to M3. Existing Obsidian handoff is reused; a complete native rich-derivation
round trip has not been newly accepted in this slice.

M2 still must complete authentic YOLO, DSA, ADRC/Mongla and bottom-up learning journeys.
M3 still must close specialist-tool round trips and source-edition/annotation contracts.
M4 still must add safe ScreenPad supporting-context pinning and inspect those journeys.
M5 carries all unresolved original P0–P8 reliability, monitor/lifecycle and learner-trial
gates. No optional notebooks, Codeforces integrations or AI tutor were installed here.

One bounded isolated Zotero control run recorded initial startup 2.05 s, unchanged
profile restart failure at 30.097 s, direct-copy startup 1.13 s and restored empty-copy
startup 1.275 s. This reproduces profile/location asymmetry; it does not resolve the
populated PDF/annotation restore regression. That release gate remains open. Do not
reinterpret an empty-profile success as populated reader recovery.

Off-device repository configuration remains **deferred by owner, post-V1**. Existing
local backups and historical acceptance remain intact. Rollback uses the scoped
installer manifest and restores application files without deleting learning records.
