# Noesis Notion research ledger

100 targeted discovery queries were executed for this redesign, plus follow-up technical verification. This is a query count, not a claim to have read 100 papers or tested 100 products. Template descriptions are design examples and marketing material, not learning-science evidence. Four marketplace layouts were visually inspected: Student OS, University Hub, the Researcher's Toolkit and Research Processing System. No paid template was purchased or copied.

## Findings that changed the implementation

| Source / class | Finding and limitation | Result in Noesis |
|---|---|---|
| [Notion linked views](https://www.notion.com/help/notion-academy/lesson/linked-views), official docs | Different workspaces can show one editable source. Filters are not security boundaries. | Reuse shared task, source and session records instead of copying trackers. |
| [Relations and rollups](https://www.notion.com/help/relations-and-rollups), official docs | Relations connect collections; CSV exports do not reconstruct those relations. | Explicit course/path/project/resource relationships; private backup manifests. |
| [Student OS](https://www.notion.com/templates/student-os-664), template artifact | Upcoming work and course galleries reduce navigation; product benefit claims are untested. | Due queues and course gallery; no fake credit progress. |
| [University Hub](https://www.notion.com/templates/university-hub-838), template artifact | Dedicated course, professor and job contexts around one overview. | Course contact fields and separate administration/opportunity views. |
| [Research Processing System](https://www.notion.com/templates/research-processing-system), template artifact | Reading passes make a paper's stopping point explicit; not every paper warrants equal depth. | Position, next action and reading state separate from reproduction. |
| [Researcher's Toolkit](https://www.notion.com/templates/collections/researchers-toolkit-notion), official collection of templates | Research includes sources, protocols, feedback and results. | Projects and experiment sessions connect sources to evidence. |
| [Dunlosky et al.](https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html), research review, 2013 | Retrieval and distributed practice have broad support; applicability varies by task and learner. | Explicit reconstruction/retry queues; reading completion never awards capability. |
| [Mawson & Kang](https://pubmed.ncbi.nlm.nih.gov/40564553/), meta-analysis, 2025 | Applied classroom studies support distributed practice; available studies limit moderator conclusions. | Choose useful later checks; no universal interval forced onto all skills. |
| [Andy Matuschak](https://notes.andymatuschak.org/zWbMsEFW9LD4vsoVhaDcF4u), practitioner analysis | Revisiting linked notes is not the same as retrieval testing. | Review asks for an independent response, not merely reopening a page. |
| [Student workflow discussion](https://www.reddit.com/r/Notion/comments/1r5cspy/how_do_students_actually_use_notion_for_semester/), anecdotal | Several contributors favour shared assignments related to course pages. Small, self-selected discussion; no consensus claim. | One task source with academic filters. |
| [Obsidian migration discussion](https://www.reddit.com/r/ObsidianMD/comments/1tgmwcw/switching_from_notion_to_obsidian_need_tips/), anecdotal | Export structure and attachments can become awkward. | Keep durable learner content local; use Notion for management. |
| [Native charts](https://www.notion.com/en-gb/help/charts), official docs | Free-plan chart allowance is limited. | One meaningful workload chart; no upgrade-dependent dashboard. |
| [Database automations](https://www.notion.com/en-gb/help/database-automations), official docs | Many automations require paid plans and have trigger limits. | No unsupported automation claims or automatic shifting of fixed deadlines. |
| [Offline pages](https://www.notion.com/help/use-pages-offline), official docs | Supported apps, per-page downloads and database limits matter; browser mode differs. | Do not promise reliable Linux-wrapper offline access; local evidence stays local. |
| [Style options](https://www.notion.com/help/customize-and-style-your-content), official docs | Native font choices and page width are limited. | Portable Mono pages plus an explicit local Iosevka styling layer. |
| [Export and backup](https://www.notion.com/help/back-up-your-data), official docs | Export is not a full workspace reconstruction. | Separate private snapshot and identity manifest. |
| [UIU course plan](https://cse.uiu.ac.bd/ug-program/course-plan/), institution | Applicable catalogue, credits and sequence; some codes conflict with descriptions. | Versioned 122-entry catalogue; four discrepancies visibly unresolved. |
| [UIU registration notice](https://www.uiu.ac.bd/notice/course-registration-notice-for-newly-admitted-students-fall-2026-trimester/), institution, October 2026 | Institutional dates do not establish personal registration. | Two institutional calendar records, one planned verification action, no invented enrollment. |
| [Portal configuration](https://flatpak.github.io/xdg-desktop-portal/docs/configuration-file.html), official technical docs | Interface-specific routing avoids replacing unrelated portal functions. | KDE file preview dialog with GTK fallback; preserve Hyprland capture. |

## Rejected or deferred

No purchase or copying of a commercial template. No third-party weather widget, quote feed or analytics endpoint gets private study data. No artificial mastery percentage. No automatic form submission, university registration, payment, grade inference or database-per-course duplication. No overlapping self-hosted management stack. No flashcard scheduler applied indiscriminately to proofs, research or hardware experiments. New UI controls must reduce the steps in a real workflow rather than simply increase feature count.
