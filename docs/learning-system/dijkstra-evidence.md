# Dijkstra through the shared learning thread

This slice adds no algorithm-specific Noesis page, backend record type or executor.
The same Practice → question/Frontier → prerequisite → Git implementation → Lab
→ changed task → return-to-origin contracts used by convolution support Dijkstra.
All captured reasoning and outcomes are **agent-authored disposable acceptance**,
not the owner's learning history or evidence of educational effectiveness.

## The usable workflow

Start a shortest-path problem in Practice and predict before checking a solution.
Record the original reasoning and failure. **Investigate the missing mechanism**
creates an ordinary question with exact owner, problem identity and assessment
reference. Follow an optional greedy-invariant prerequisite and return with Back
or the origin action; the original question and draft remain intact.

After ending the protected attempt, **History & next steps → Connect implementation**
connects an existing Git repository and an optional exact code file. In a question,
the same action is available through Ctrl+. or More. A new implementation opens
its Lab working page rather than remaining inside Practice. New experiment runs
observe the current Git revision and retain that exact code entry point.

The installed [example scaffold](../../home/.local/share/sensei-learning/examples/dijkstra/README.md)
contains an empty `shortest_paths` skeleton, inspectable cases, an independent
Bellman–Ford oracle and instructions. Copy it into your own new Git repository.
Noesis does not execute it when opening a record. Write the implementation in the
editor, commit it, then explicitly run `python check_cases.py --output observations.json`.
Inspecting the oracle or another solution counts as reference assistance when it
informs reconstruction; software cannot observe every external exposure for you.

Preserve failed outputs separately. Begin a run from the implementation, attach
actual output artifacts and code revision, inspect their checksums, and record a
comparison. A comparison stays labelled reported evidence; an artifact opening
or editor launch never becomes an execution or understanding claim. Preserve the
invariant, failure cues and remaining proof questions in the existing concept and
study history, and open the exact concept note in Obsidian for a full derivation.

**Question, mechanism & implementation** opens a bounded, collapsible thread panel.
It uses existing relationships and owner references, and stays out of a protected
attempt's reasoning surface. Changed-problem creation no longer requires prior
success: curiosity and failure analysis do not wait for an artificial gate.

## Executed acceptance

`scripts/check-noesis-dijkstra.py` uses real native Qt pointer/keyboard input,
normal and fullscreen windows, ScreenPad compositor captures, and 200% reflow.
It creates questions, prerequisites, implementations, runs, artifacts, comparisons
and transfer tasks through the UI. Initial problem/concept/reference fixtures are
seeded as ordinary records; no CLI repair completes the learning journey.

A real isolated Alacritty/Neovim session opens the skeleton file. Native editor
commands author the test implementations and explicitly execute the test runner.
Git commits distinguish the skeleton, discovery/finalization mistake and correction.
Outputs preserve the implementation SHA-256, actual commit, dirty state, conventions,
observed values, exceptions and independent expectations.

- Skeleton: eight recorded `NotImplementedError` failures.
- Wrong first-discovery algorithm: B=10 instead of the independently checked B=2;
  additional adversarial failures remain preserved.
- Corrected implementation: eight cases agree, including stale entries, zero-cost
  cycles, disconnected vertices, parallel/equal-cost edges, a singleton graph,
  negative-edge rejection and an unreachable negative edge.
- Changed directed problem: find distances **to** T using reversed edges. Its check
  is withheld from the initial run and explicitly invoked with `--transfer` after
  the prediction and deliberate reference reveal. T=0, B=2, A=3, C=3; X is unreachable.
  This is an assisted changed-case check, followed by a separate unaided retry of
  that same case. The retry is not a previously unseen independent transfer result.

The test checks that selecting “none” cannot erase earlier reference exposure,
that a new attempt has its own assistance state, and that no capability decision
is awarded. It follows the optional prerequisite and exact origin, verifies an
isolated native Obsidian handoff to the correct concept file, restarts Noesis and
recovers the original question, draft and connected implementation/evidence.

## Shared improvements and release limits

Both convolution and Dijkstra now start reconstruction with an empty skeleton.
Existing convolution implementations and historical results are unchanged. Practice
retains its statement/reasoning anchors and chosen surface; navigation records the
view before changing workspaces. Comparison fields have persistent labels, wrapped
text and a visible Save action at larger scales. Lab uses its own actions and moves
extra run notes into details rather than duplicating a Markdown inspector.

No vault schema migration, new authoritative learning-thread store, framework,
notebook dependency or private learning mutation is introduced. Rollback uses the
existing scoped installer and replacement backups. Original P0–P8 acceptance remains
open: populated Zotero restoration, wider recovery/fault journeys, other domains and
the owner's real learner trial are not completed by this slice. Off-device backup
configuration remains explicitly deferred by owner.

For the owner trial, start with an unfamiliar graph and write your own implementation.
Check whether the failure-to-question action is discoverable, prerequisites clarify
rather than distract, statement/reasoning stay accessible, the editor and Obsidian
return preserves context, and the assisted/unaided distinctions remain understandable.
