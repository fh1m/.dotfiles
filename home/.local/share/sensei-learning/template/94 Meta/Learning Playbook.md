# Choose the work, then the practice

A useful session ends with a capability tested, a precise blocker found, or a
model corrected. Reading position and demonstrated understanding are different.

| Mode | Use when | Leave with |
|---|---|---|
| Pattern study | Broaden recognition | Problem cue, useful idea, why it fits, nearby wrong idea |
| Interface exploration | Start using an unfamiliar tool | Contract, cost/assumptions, working case, failure boundary |
| Independent reconstruction | Deepen a load-bearing concept | Your attempt before feedback, exact gap, reconstruction |
| Build / reproduce | Learn by implementation or experiment | Tiny baseline, test oracle, observed comparison, discrepancies |
| Transfer test | Check whether understanding travels | Changed constraint, prediction, independent evidence |

In Noesis select a note → choose the mode → state a concrete goal → Begin practice.
Recall hides the reference by default. Reveal it deliberately; assistance is useful,
but record it. The practice note is editable in Obsidian or Neovim and links back to
the source. Confidence is never awarded by the session generator.

## Keep the interface small
A source is material. A concept is your working model. A practice session is actual
work. A project is a capability built. Link these when it helps; don't duplicate a
paper into a dozen compulsory forms. Free notes and arbitrary folders remain valid.

## If stuck
Write the current idea and its failed prediction. Try a small concrete example,
alter a constraint, inspect the interface or take the smallest useful hint. Repair
only the gate that blocks the next meaningful attempt. Park deeper curiosity.
Stop when effort stops producing useful thinking; don't erase the failed work.

## Build defensively
Choose a small vertical slice and a trustworthy comparison before optimizing.
For ML inspect data and labels, preserve split/preprocessing/version details, try
a tiny batch and compare reference outputs. A decreasing loss is not proof of a
correct implementation. For hardware name units, frames, calibration and limits.
Keep computation testable apart from I/O and hidden state.

## Review without theatre
Close the source, reconstruct a mechanism or solve a case, then check feedback.
Later change the context. Record evidence and schedule a retry if useful. A streak,
page count, elapsed timer or generated explanation is not mastery. Use the method
that serves today's task; deep study is expensive and should be chosen deliberately.
