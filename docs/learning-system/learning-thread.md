# A reusable learning thread

Convolution is a bounded reference lesson, not a new learning architecture. Its
arithmetic adapter is specific; its durable interactions use existing contracts.

A thread is a **derived view** of an owned origin, a current question, navigation
frames, related records and their activities. There is no new authoritative thread
record, competence database or copied source notebook.

| Contract | Existing authority | Convolution reference |
|---|---|---|
| Origin and question | Owned record UUID; question `parent_ref`, evidence references | Failed reconstruction → question linked to exact assessment |
| Reasoning | Study/attempt activities; local unsaved drafts; rich Markdown in Obsidian | Prediction and explanation remain separate from computed output |
| Descent and return | Contextual prerequisite relationship with role/reason; owned navigation history | Optional weighted-sum prerequisite → exact originating question |
| Implementation | Git repository, revision, dirty state; optional contained `code_entrypoint` | Open the specific `convolution.py`, not a generic repository browser |
| Experiment | Existing experiment, configuration, comparison and artifact records | Explicit local execution compared with an independently specified NumPy oracle |
| Understanding | Existing scoped capability decision and actual evidence references | No automatic claim from running the supplied starter or matching output |
| Continuity | Owner/UUID navigation, saved anchors, drafts, receipts and specialist handoffs | Close/restart and return preserve original investigation and question |

Exploration never needs a competence claim. Using an abstraction, explaining it,
reconstructing independently, assisted work, failure and an unanswered mechanism
remain distinct. Prerequisite gates are contextual; optional descent does not block
playing, reading or creating a question. Only an explicit understanding judgment
needs suitable evidence. Unknown assistance is never silently converted to none.

Noesis coordinates the thread. Obsidian owns rich derivations/maps, Zotero owns
research sources/annotations, Git owns code history and experiment artifacts preserve
executed results. Opening a tool is a handoff, not evidence of completed learning.
The additive `code_entrypoint` field selects an existing file inside its repository;
it creates no second code authority. Local lesson preferences are resumable UI state,
not independent observations or learner claims.

## Prioritized next vertical slices

1. **Dijkstra failure → invariant → independent transfer.** Reuse Practice's protected
   attempts, assistance, exact assessment-linked questions, contextual prerequisites
   and capability evidence. Improve the problem/invariant/changed-case return path;
   a small explicitly invoked oracle test can reuse experiment/artifact provenance.
   Missing: a focused reusable-insight view and source/code line anchors. Do not
   import an accepted submission as proof of unaided reasoning.
2. **An accurately versioned YOLO paper → code → parameter experiment.** Reuse
   Research, annotation identity, Git handoff and Lab comparisons. Begin with one
   inference parameter and a clearly specified dataset/metric, preserving actual
   architecture/version. Missing: a composed thread read model connecting these
   existing views and exact code/configuration anchors. Original YOLO, YOLO11 and
   RF-DETR remain separate investigations; convolution alone establishes none.
3. **Mongla control question → ADRC derivation → simulation → evidence.** Reuse owned
   project references, Obsidian, prerequisites, experiment configuration and figures.
   Start with one actual plant/control question from the inspected project, not an
   invented vehicle model. Missing: precise simulation-run handoff and visible
   evidence-medium labels throughout. Simulation, bench and underwater evidence
   remain distinct; no controller superiority is inferred from one run.

Before adding state, test whether a bounded read model over these links/activities
answers the question. Duplicate state would arise from a separate thread database,
a second score graph, copied Zotero annotations, copied authoritative code or a
parallel notebook of observations unlinked to existing experiments. Avoid these.

Obsidian URI/CLI and Bases can expose existing Markdown properties. marimo/SymPy
and literature discovery remain selective pilots, not dependencies of browsing or
learning. The small native lesson plus plain Python/Git already supports convolution;
installing a notebook stack is unnecessary for this acceptance slice.

This ordering is a recommendation after convolution, not implementation of those
three domains. Original P0–P8 gates remain in force; populated Zotero restoration,
full cross-domain journeys and the owner's sustained learner trial remain open.
Off-device repository configuration remains deferred by owner, post-V1.
