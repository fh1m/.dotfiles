## Findings, not yet changed

**Security**
- No host firewall is active. `ufw` was deliberately left out of `packages/core.txt`. Listeners on all interfaces: KDE Connect (1716 tcp/udp), Syncthing (22000, 21027), Tailscale (41641), mDNS (5353), and systemd-resolved LLMNR (5355, which is on by default). Proposed: an nftables policy that allows Tailscale and LAN only for KDE Connect and Syncthing, plus `LLMNR=no` in `resolved.conf.d`. Needs root, so it is not applied.
- Sudoers: `fh1m` has `(ALL) ALL` with a password. Three NOPASSWD helpers under `/usr/local/libexec` are narrow and root-owned. Confirmed `sensei-usb-audit.socket` has its `@USER@` placeholder rendered (`SocketUser=fh1m`).

**Drift between repo and live system**
- Live Hyprland runs the `sensei` name (`~/.config/quickshell/sensei`, `hypr-sensei.lua`, `sensei-*` binaries). The repo says `wrayth`. Functional content is identical; only names differ. Naming decision pending.
- `/usr/local/bin/power-profile-auto.sh` is referenced by a udev rule but is not tracked in the repo.
- `/etc/udev/rules.d/99-duburi-serial.rules` and `99-realsense-libusb.rules` are live but not tracked (robotics hardware, probably belongs in the robotics setup).

**Shell (`home/.zshrc`)**
- `ss` is aliased to `rmpc`, which shadows the socket-statistics tool. Verified: `ss` runs rmpc.
- Aliases point at tools that are not installed: `hwatch`, `hyperfine`, `diskonaut`, `rmpc`, `ncmpcpp`, `gping`, `hexyl`, `exiftool`, `bandwhich`.
- `alias rm="trash"` changes `rm -rf` habits in interactive shells.
- Hardcoded `/home/fh1m` in `.zshrc` (`go/bin`, `.spicetify`, `.local/bin` PATH entries). PATH entries are duplicated.
- ROS block sources `/opt/ros/humble`, but the host has no `/opt/ros` and the robotics stack targets Jazzy in the container.

**Design**
- Three Hyprland layers (`hyprland.lua` → `hypr-wrayth.lua` → `custom-setup.lua`) override each other with `unbind`/`bind` pairs. Hard to reason about. Proposed: one layer for personal binds with a single unbind list.
- Two installers (`install.py` and wrayth's `install.sh`) both manage `~/.config/hypr`, kitty and the bin links. Pick one owner.
- `wrayth-shell`, `wrayth-deck-reset` (autostart targets) are not on the live PATH under those names. The live system uses `sensei-*`.

**Tests**
- `pytest` is not installed on this machine, so `tests/` could not be run here.

- `system/etc/systemd/resolved.conf.d/10-sensei-no-llmnr.conf`: `LLMNR=no`.
- Not applied yet. Applying needs a rollback timer, for example `systemd-run --on-active=90 nft -f <previous ruleset>`, so a lockout heals itself.
